# 틈틈이 데이터

출퇴근길 아이폰 웹앱 **틈틈이**가 받아 가는 뉴스·읽을거리 파일이에요.

| 파일 | 내용 | 바뀌는 때 |
|---|---|---|
| `data/news.json` | 13개 분야 뉴스(정치·국회·생활정책·사회·경제·주식·국제·IT과학·스포츠·연예·문화·패션·행사) | 새벽 4시 20분(전체), 오후 4시(빠른 업데이트), 관리자 요청 때 |
| `data/reading.json` | 역사(한국사·현대사·우리 동네 역사)·생활(세탁·청소) 읽을거리 | 매주 일요일에 더해짐 |
| `data/daily/*.json` | '오늘의 한 장' 카드(속담·사자성어·상식·유래·우리말) | 상식·유래가 이틀마다 5장씩 더해짐 |
| `data/brain.json` | 두뇌 게임 문제(하루 두 판 × 3문제, 최상 난이도). 정답은 글자로 없고 확인값만 | 날마다 새벽 1시 40분에 하루 앞선 판을 더함 |
| `data/version.json` | 위 파일들이 언제 바뀌었는지, 조사를 마친 시각, 다음 조사 시각 | 조사할 때마다 |

- 앱 주소 설정: 앱 `index.html`의 `<meta name="tteum-data-base">`에
  `https://raw.githubusercontent.com/woos-lee94/-tteumtteumi-data/main/data/` 가 들어 있어요.
- 앱은 작은 `version.json`만 자주(열 때, 켜 둔 동안 10분마다) 받아 보고, 바뀐 파일만 새로 받아요. 조사(토큰)를 쓰지 않아요.
- 조사는 Claude 예약 작업이 해요.
  - 새벽 4시 20분 '틈틈이 뉴스 업데이트': `pipeline/RUNBOOK.md` (분야마다 새 기사 2건 안팎, 일요일 읽을거리, 이틀마다 카드)
  - 오후 4시 '틈틈이 빠른 업데이트': `pipeline/RUNBOOK_QUICK.md` (지난 판 이후 읽을 만한 새 소식, 없으면 0건)
  - 새벽 1시 40분 '틈틈이 두뇌 게임': `pipeline/RUNBOOK_BRAIN.md` (다음 날 두 판 6문제, 규칙은 `pipeline/brain_spec.md`)
- 기사는 여러 언론 보도를 교차 확인해 쉬운 말로 새로 쓴 요약이고, 기사마다 원문 출처를 달았어요.
- 오래된 기사는 자동으로 정리돼요(최근 3일 기사 중심, 모자라면 5일 안쪽 기사로 분야별 5건까지 채움, 끝난 행사는 빠짐). 새 기사 수는 분야별 '최근 3일' 기사 수를 보고 정해요.

## 관리자 '지금 새로 조사'
- 관리자 폰의 틈틈이 앱 → 'Claude에서 실행' → 관리자 Claude 계정에서 예약 작업 '틈틈이 빠른 업데이트'를 바로 실행 → 이 저장소에 올라가면 모든 사람 앱이 다음 확인 때 받아 가요.
- 조사는 관리자의 Claude 계정으로만 시작돼서, 다른 사람은 조사를 시작할 수 없어요.
- 마지막 조사를 마친 지 50분이 안 됐으면 작업이 스스로 건너뛰어요(`pipeline/updates.json`의 cooldownMinutes).

## 두뇌 게임
- 앱이 오전 6시·오후 5시에 판(3문제)을 열어요. 난이도는 늘 최상, 정답은 딱 하나.
- 정답은 `data/brain.json`에 글자로 넣지 않아요. `h = sha256("tteum-brain|문제id|다듬은 정답")`만 두고, 풀이(`x`)는 정답으로 만든 열쇠로 잠가요. 앱은 적은 답으로 같은 값을 만들어 맞는지 보고, 맞힌 경우에만 풀이를 풀어요. 틀리면 '틀렸어요'만 보여 줘요.
- 문제는 세 번 확인해요: ① verify 코드로 모든 경우를 따져 답이 하나인지 ② 정답을 모르는 에이전트가 따로 풀어 같은 답인지 ③ 다른 에이전트가 다른 답·애매한 문장·너무 쉬움을 찾는 반박 검사. 하나라도 걸리면 버려요.
- 정답·풀이가 든 후보 파일은 `work/brain/`에만 두고 올리지 않아요(`.gitignore`). 도구: `python3 pipeline/brain.py need|recent|check|strip|compare|verdict|merge|build|validate|status`.
